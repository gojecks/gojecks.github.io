This reference covers the JavaScript API surface. For the query-string/object language used by jQl, see the dedicated jQL reference.

Getting started

jdb(name, version)

jdb(name, version)
ArgumentTypeRequired
namestringYes
versionnumberYes

Returns a builder with .open(config), plus .isClientMode() and .requiresLogin() for opting into those modes before opening.

.open(config) → jDB Promise 
jdb('myapp', 1)
    .open({ storage: 'indexeddb' })
    .onCreate(function (e, next) {
        e.result.createTbl('users', [{ id: { type: 'NUMBER', AUTO_INCREMENT: 1 }, name: { type: 'VARCHAR' } }]);
        next();
    })
    .onUpgrade(function (e, next) {
        next();
    })
    .onSuccess(function (e) {
        var db = e.result; // DatabaseInstance
    })
    .onError(function (e) {
        console.error(e.message);
    });

onCreate fires the first time a database is opened; onUpgrade fires when an existing database is opened with a higher version. Both receive next() to call once setup is done. onSuccess/onError (or .then(success, error)) resolve with { result, message, type }, where result is the DatabaseInstance you'll use for everything else.

isClientMode()

Marks the connection as client-facing (production) before .open(), disabling debugging affordances.

jdb('myapp', 1).isClientMode().open({ storage: 'indexeddb' });

requiresLogin()

Opens in a restricted login mode: the resolved instance only exposes api(), close() and jQl() until the app authenticates and re-opens normally.

jdb('myapp', 1).requiresLogin().open({ serviceHost: 'https://api.example.com' });

jDB promises

.open() returns a jDB Promise: .onSuccess(fn), .onError(fn), .then(success, error), .catch(fn) and .finally(fn), plus the .onCreate/.onUpgrade event hooks shown above. Most instance methods (transaction, jQl, batchTransaction, storeProc().execute) return standard native Promises instead — check the signature on each method below.

db.transaction(table, mode)

→ TableTransaction
ArgumentTypeNotes
tablestring | arrayA table name, or ["a as x", "b as y"] for a multi-table (join) transaction.
modestringread (default), write/writeonly, or readwrite.

Read-mode transactions expose select/qsl; write-mode transactions expose insert/insertReplace/update/delete. See Transaction instance below.

db.transaction('users', 'writeonly')
    .insert({ name: 'Ada' })
    .execute()
    .then(res => console.log(res));

db.jQl(query, params)

→ Promise

Runs a query in jDB's own query language. Full syntax, every command, and the field-type system live on the jQL reference page.

db.batchTransaction(transactions, rollBackOnError)

→ Promise
ArgumentTypeNotes
transactionsarrayArray of { type, data, query, table, hardInsert }, where type is insert, update or delete.
rollBackOnErrorbooleanDefault false.
db.batchTransaction([
    { type: 'insert', table: 'users', data: { name: 'Ada' } },
    { type: 'update', table: 'users', query: { id: 1 }, data: { role: 'admin' } }
], true);

Transaction instance

.insert(data, hardInsert, tableName)

Write-mode only. data is an object or array of objects. hardInsert bypasses soft-insert de-duplication.

.insertReplace(records, updateRef)

Upserts by updateRef (defaults to the table's primary key).

.update(updateRecords)

updateRecords is an array of [condition, data] pairs — one update per pair.

.delete(query, tableName)

query is a condition object; omit it to delete every row.

.select(fields, definition)

Read-mode only. definition is { where, join, limit, orderBy, groupBy, ... } — the same shape jQl's select command builds internally from its clause syntax.

.qsl()

Quick Search Language: returns dynamically generated findBy<Column>(value, fields) finders for every column on a single-table transaction, or findByColumn(columnName, value, fields) for a multi-table one.

db.transaction('users').qsl().findByEmail('ada@example.com');

.execute(disablePushToServer, fromBatch, rollbackOnError)

→ Promise

Runs every queued operation on the transaction (insert/update/delete/select calls can be chained before calling .execute() once). Also available: .dataProcessing(boolean) to toggle validation/default-value generation before inserting.
